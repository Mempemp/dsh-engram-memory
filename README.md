# dsh-engram-bridge

**Память engram приходит в ход сама.** Плагин DeepSeek Harness: на `agent/pre-step` последнее сообщение пользователя превращается в поисковый запрос по базе engram, и до двух записей в жёстком бюджете добавляются в ход.

Инструменты engram работают, когда модель про них вспомнит — а в разговоре про прошлые решения она вспоминает не всегда. Это второй, обратный путь: не модель спрашивает память, а память приходит вместе с вопросом.

Замена MCP-серверу не делается: там pull-путь (модель сохраняет и ищет), здесь push-путь. Стор один и тот же — `engram.db` открывается **только на чтение**, пишет по-прежнему engram.

## Чего в плагине нет

- нет своего процесса, порта, демона и сети;
- нет ключей и моделей: поиск лексический, FTS5/BM25 внутри engram;
- нет нативных модулей — используется `node:sqlite` самого рантайма;
- нет токенов в простое: нет совпадений — нет инъекции.

## Установка

```
dsh plugin --profile web add <путь-или-URL>
```

Из бандла 1С плагин приезжает строкой каталога (`kind: plugin`) вместе с MCP-сервером engram.

## Настройка

Всё необязательное. Значения берутся из того же файла, что читает шим MCP-сервера, — `%LOCALAPPDATA%\DSH-1C\engram-mcp.json` (путь переопределяется `ENGRAM_MCP_CONFIG`):

```json
{ "dataDir": "D:/engram-data", "project": "my-project" }
```

| ключ | по умолчанию | смысл |
| --- | --- | --- |
| `enabled` | `true` | выключить плагин целиком |
| `budget` | `1200` | бюджет инъекции в символах |
| `topK` | `2` | сколько записей максимум |
| `dataDir` | `%USERPROFILE%\.engram` | где лежит `engram.db` |
| `project` | `.engram/config.json` в рабочем каталоге, иначе имя каталога | проект записи в базе |

## Как строится запрос

- запрос — последнее сообщение пользователя; слова от трёх знаков, стоп-слова выброшены;
- каждое слово ищется префиксом (`диариз*` находит «Диаризация»), а длинные — ещё и усечёнными на два знака (`диаризации` → `диаризаци*`): морфологии в engram нет, и это ловит падежи;
- порядок — BM25; мягко удалённые записи и записи чужого проекта отбрасываются;
- запись, уже показанная в этой сессии, не повторяется;
- запись, не влезающая в бюджет, отбрасывается целиком, а не обрезается: обрубок стоит токенов и не приносит ответа.

## Границы

- `node:sqlite` в Node 22/24 помечен экспериментальным и печатает `ExperimentalWarning` в лог — поведение от версии к версии не обещано;
- субагенты инъекцию не получают намеренно: у них своя задача и свой контекст;
- проект определяется по рабочему каталогу хода, поэтому запись, сохранённая из другого каталога, найдётся только при совпадении имени проекта.

## Проверка

```
node test/store.smoke.mjs   # поиск, бюджет, промахи
node test/hook.smoke.mjs    # pre-step: инъекция, дедупликация, границы, отказы
```

`store` прогоняет 19 запросов (точная форма, падежи, словообразование, множественное число, синонимы, идентификаторы, регистр) на 10 записях — recall@1 19/19 и на синтетической базе со схемой engram, и на настоящей базе, собранной CLI engram v2.0.0, ~0,3 мс на запрос. `hook` проверяет саму инъекцию на поддельном `ctx`: сообщение встаёт перед репликой пользователя, повтор не инжектится, субагент и запрос из одних стоп-слов пропускаются, без базы ход не меняется, `dispose` освобождает стор.

Если рядом нет бинарника engram, вторая половина `store` пропускается — задайте `ENGRAM_EXE`.
